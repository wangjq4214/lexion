# 局域网发现与安全配对

**Ticket ID:** T0004
**Source:** [Spec 0004](../../spec/0004-offline-lan-learning-data-sync.md) §Requirement 4；[ADR 0012](../../adr/0012-relay-applied-operations-through-paired-devices.md)
**Status:** In Progress

## Goal

在 LAN 自动发现附近设备，经 Noise 加密连接与首次配对码核对，只让明确配对的设备建立可复用的信任关系；可独立验证配对，不需要尚未完成的学习数据同步。

## Affected Surfaces

- **Tauri/Rust 设备服务：** `src-tauri/src/lib.rs` 附近的发现、加密连接、授权身份持久化和拒绝未配对连接的边界。
- **桌面配对交互：** 同步入口的设备发现、配对码展示/确认、配对成功/失败反馈、已配对设备可能转发其他设备日志的说明及 Tauri 命令契约。
- **局域网环境：** mDNS 与 Noise 会话；未发现设备时本地功能不受影响。

## Approach

发布与查找局域网对端，用 Noise 建立加密会话，首次在界面手动核对与该会话绑定的配对码，核对成功后持久记住被授权设备。之后只有直接确认过的设备才能以保存的身份重连；A 配对 B、B 配对 C 不授权 C 直接连接 A，但 A 可通过已配对的 B 接收其已生效的 C 日志（转发由 T0005 实现）。配对界面需说明已配对设备可能转发其他设备的学习数据。配对失败、取消及未发现对端时不授予直接连接权限。具体 Noise 模式和码呈现样式在满足上述安全契约的前提下由实现验证，不在票据中冒充既定需求。

## Dependencies and Coordination

- **Blocked by:** 无；可用独立连接/认证测试验证，尚不交换学习数据。
- **Blocks:** T0005，自动同步只能建立在双方已明确配对的连接上；转发的第三方作者不必与接收方直接配对。
- **Coordination risks:** T0005 将使用同一 Rust 会话与前端同步入口；先确立已授权身份、连接状态及错误反馈接口，不并行写入同一 UI 组件而不协调。

## Acceptance

- [ ] 局域网内设备能经 mDNS 互相发现并启动 Noise 加密会话；首次连接双方展示并核对该连接的配对码，确认后持久记住对端身份，重启后无需再次首次确认。
- [ ] 配对码不一致、未确认、取消或身份冒充时不建立授权关系，不允许未配对设备直接连接或交换学习数据；已配对设备可以在后续同步中担保它转发的第三方操作来源。
- [ ] A-B、B-C 各自配对后 C 仍不能直接连接 A；配对界面说明 A 与 B 同步时可能收到 B 已生效的 C 日志；局域网不可用时保留本地学习能力并呈现可理解状态。

## Out of Scope

- 交换学习数据、跨公网中继，以及 mDNS 失败时的手动地址发现。
