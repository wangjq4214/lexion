# 持久变更与确定性重放

**Ticket ID:** T0001
**Source:** [Spec 0004](../../spec/0004-offline-lan-learning-data-sync.md) §Requirement 1、3、5；[ADR 0009](../../adr/0009-support-offline-multi-device-lan-sync.md)
**Status:** Done

## Goal

建立可独立验证的离线变更与重放契约，令本地写入和变更记录一致，多个设备能够对同一组操作得出相同顺序及状态，而非覆盖对方 SQLite 文件。

## Affected Surfaces

- **Rust/SQLite 持久层：** 同步设备/变更身份、提交与重放状态；对应 `src-tauri/src/wordbooks/repository.rs` 的存储边界。
- **纯重放约定与测试：** 本机顺序、已知因果关系、并发确定性排序、重复接收和中断恢复所需的接口。

## Approach

给后续词书、学习事件和设置写入提供可复用的持久变更身份与原子提交边界。重放时先保留各设备及已知因果顺序，再用稳定顺序处理并发；后重放的操作生效。记录用于排序的因果信息与学习事件的发生时间要分开；重放和传输不能只依靠不同机器的墙上时间。以可控虚拟设备和操作验证契约；不在此票选择尚未定稿的具体线协议或排序算法。首发仅从全新数据开始，不自动清库或编造旧库的操作历史。

## Dependencies and Coordination

- **Blocked by:** 无。
- **Blocks:** T0002、T0003（写入/重放需要此契约）；T0005（交换需要稳定身份、增量读取及幂等应用边界）。
- **Coordination risks:** 与 T0002/T0003 共同触及仓储层；先确定最小操作契约并用测试固定，业务操作由各后续票接入。

## Acceptance

- [ ] 同一操作的本地结果及其变更记录原子提交；失败不会只留下其中一方。
- [ ] 对有因果关系与并发关系的测试操作，不同到达顺序的两个虚拟设备得到相同重放结果；设备时钟偏差不颠倒因果先后。
- [ ] 同一操作重复收到或在重启/中断后重新应用不会产生额外效果；已应用身份可持久恢复。
- [ ] 空库可以初始化记录与重放能力；打开旧库不触发自动删除，也不把旧汇总值表示成历史操作。

## Out of Scope

- 具体词书、错题或复习业务操作接入；真实网络交换和配对。
