# 词书、词条与收藏同步（T0002）

- **Input:** `.grimoire/ticket/0001-offline-lan-learning-data-sync/T0002-wordbooks-and-favorites.md`，Spec 0004 §1–3、ADR 0001/0002/0008/0009
- **Status:** Proposed

## Summary

将导入/确认替换、整书及单词删除、收藏增删接入 T0001 原子操作日志与确定性重放。复用本地行号作为 UI 句柄，但跨设备操作仅使用词书名称和规范化词义配对；投影持久保存本地行号映射，保证重建不会错误指向别的词。旧库不清理、不伪造历史。

## Source intent and acceptance

1. 双空库离线导入与收藏双向合并、独立于书：步骤 1–3、双库测试。
2. 同名确认替换原子生效，删除不波及收藏/错题：步骤 2–3、回归测试。
3. 并发删改/替换确定性收敛、无跨机行号误删：步骤 1–3、交错重放测试。
4. 收藏重复和回滚去重、既有命令行为：步骤 2–4、错误注入及完整 Rust 测试。

## Design impact

- **Create** `src-tauri/src/wordbooks/repository/content.rs`: 版本 1 业务 payload、校验及 Projection；只拥有词书和收藏及其来源覆盖，不清除错题/复习记忆。本地 ID 映射为重放保留的内部表，不作为 wire identity。对不属于自己的 payload 拒绝而非忽略；T0003 接入时需合成投影并协调 reset。
- **Modify** `repository.rs`: 保留现有 Tauri 签名与 Excel 解析/确认；新库写入经日志，旧库继续原行为。删除入口从本地 ID 解析稳定目标；空操作不记变更。映射使书名、(书名,规范英文,中文) 在重放中稳定命中同一个本地行号。
- **Modify if needed** `replay.rs`: 保证未来业务投影组合的原子重建接口可用，不引入网络协议。

## Implementation steps

1. 定义 JSON tagged 内容操作（完整导入替换、删除书、删除配对、收藏添加/移除）；校验空名称/词义和导入重复配对。投影重放按规范顺序以同名书为目标，替换删除旧内容及覆盖，不触及独立收藏、错题。保存本机 row-ID 映射以便重建 UI 句柄稳定；测试同名并发与乱序。
2. 仓储新库写路径通过 append_local 提交；本地 ID 查询稳定名称/配对，空操作及未经确认的重复名称不提交；保留旧库行为与错误契约。失败时日志、业务和序号共同回滚。
3. 双 SQLite 库互换 changes_since/ingest，验证同名替换、不同书导入、删除、收藏生命周期及不同本地 ID；添加延迟并发与重复收取/失败回滚测试。
4. 跑 Rust 全量测试和 fmt，检查 diff 中无其他写入绕过上述四类操作；必要时修复集成问题。

## Edge cases

| Condition | Expected behavior | Owning step |
| --- | --- | --- |
| 同名再次导入未确认 | Conflict，原操作和内容不变 | 2、测试 |
| 同名并发导入/删除，迟到操作 | 规范顺序最后有效操作胜出，不按到达/墙钟 | 1、3 |
| 两设备行号不同但删除同词书配对 | 只删除指定书和配对，不删除相同行号的其他词 | 1、3 |
| 收藏在源书删除后 | 保持；重复添加无重复成员 | 1、3 |
| 非法/重复 payload 或数据库投影失败 | 整个事务回滚，无虚假成功记录 | 1、3 |
| 有旧数据的库打开 | 保留旧数据和既有本地操作，不声称旧历史可同步 | 2、4 |

## Verification strategy

Rust 临时双库交换不同抵达顺序、冲突与重启；检查表中词义、收藏和错题而非行号；故障注入检查日志计数与操作结果；`cargo test`、`cargo fmt --check`。T0003/T0005 负责完整复习事件和实际传输，当前不宣称网络端到端同步。

## Risks and open questions

- 全量重建耗时随日志增长；先保证正确性，后续测量优化。
- T0003 共用日志投影时必须合成业务 decoder/reset/apply；在其接入前不能收取非本票 payload。
- 与 T0003 尚未同步的复习覆盖写入可能在重建时变化；保留不属于被替换/删除的来源数据，并在 T0003 中将覆盖事件纳入统一重建。
