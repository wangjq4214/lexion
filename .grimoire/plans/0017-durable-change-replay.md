# 持久变更与确定性重放（T0001）

- **Input:** `.grimoire/ticket/0001-offline-lan-learning-data-sync/T0001-durable-change-replay.md`
- **Date:** 2026-09-26
- **Status:** Proposed

## Summary

建立 Rust/SQLite 中独立于网络和具体业务操作的变更日志、事务写入与确定性重放基础。每条操作有稳定的设备身份、本机序号、因果前驱、版本化内容；发生时间另存，不参与排序。本票用测试用投影验证原子性、去重、乱序收敛和崩溃恢复；词书/收藏与学习事件/设置的真实操作编码和投影接入分别留给 T0002/T0003，配对与传输留给 T0004/T0005。只允许全新数据建立可重建的同步基线；打开旧库不删除旧数据，也不伪造历史变更。

## Design impact

### 变更身份与纯排序契约

- **Action:** Create
- **Location:** `src-tauri/src/wordbooks/repository/replay.rs`（或同级模块，按实际 Rust 模块布局确定）
- **Responsibility:** 定义 `DeviceId`、`ChangeId`（设备 + 单调序号）、版本化操作信封、显式前驱集合、可选业务发生时间，以及纯拓扑排序；前驱优先，当前可选节点以规范化 `ChangeId` 字节序打破并发平局。检测环、缺失前驱和同身份不同内容；排序与系统时间无关。
- **Relationships:** 被仓储的提交、收取、导出与投影重建调用；未来的 T0002/T0003 实现有版本的业务操作解码及投影，T0005 使用已授权的导出/导入接口。
- **Rationale:** 不把排序与学习事件时间、SQLite 自增行号或通信到达顺序混合；不引入泛型 CRDT 或网络线协议。本票先固定可测试的内部信封，外部序列化格式由 T0005 决定。

### SQLite 持久化与事务边界

- **Action:** Modify/Create
- **Location:** `src-tauri/src/wordbooks/repository.rs` 的 `initialize`、`connect`，新增仓储子模块/测试模块（如上）
- **Responsibility:** 在初始化时持久化设备身份、下一个本机序号、同步基线状态和不可变操作日志（唯一身份、规范内容、前驱、来源、应用状态）；用 SQLite 事务同时提交本地操作与投影结果，或接收操作及重建结果。重启可恢复去重与待补前驱状态；提供按设备序号游标读取缺失操作的接口，不能以单一全局游标跳过空洞。
- **Relationships:** 复用 `WordbookRepository::connect` 的连接生命周期和现有 SQLite 事务惯例；仓储暴露受控的 `append_local` / `ingest` / `changes_since` 等内部接口，闭包或投影处理器接收同一 `Transaction`。后续业务票必须把已有仓储写入改为走此边界。
- **Rationale:** 日志与业务结果位于同一数据库事务，避免双写；不将最终汇总值或另一台设备的整个 DB 作为同步单元。稳定设备身份只在空库创建一次，序号分配在写事务内；日志不随短期提交 token 清理。

### 可重建投影与旧库保护

- **Action:** Create/Modify
- **Location:** 同一仓储子模块与 `initialize`
- **Responsibility:** 保留全量不可变操作作为真相；新到的并发操作可能排在已应用操作之前，因此在同一事务内按规范全序重新计算受影响的投影（首版允许从空基线全量重建，性能测量后再优化）。旧库先检测是否已有学习/词书/设置的非默认持久数据，再记录“不可从空基线重建”状态；保留旧数据可用，不对其开放会覆写投影的重放。升级检测必须先于创建或插入默认行；状态写入与 schema 迁移保持原子。
- **Relationships:** 测试用小型投影证明重建契约；T0002/T0003 负责覆盖真实业务表的安全重建及稳定词书/词条目标，不复用当前本机整数行号当跨设备标识。
- **Rationale:** 仅增量地在到达顺序应用“最后写入胜出”不能保证迟到并发操作的收敛；旧汇总数据没有事件历史，不能用清库或合成操作掩盖。

### 设计待验证点

- 收取端可先持久保存缺失前驱的操作，但不能在前驱完整且校验通过之前应用；本机创建操作以当前已知的因果前沿为前驱，并保持同设备序号连续。T0005 必须按直接配对关系过滤来源和前驱：不得经 B 透传未获 A 授权的 C 的操作；不完整依赖应报告待补/拒绝，而不是默默跳过或伪造。
- `changes_since` 的游标是各来源已知的连续序号（水位加空洞处理），并非应用顺序或设备时钟。未来若跨版本 payload 不可解码，保留日志但暂停投影并显式报错，不可把未知操作当已成功应用。
- `pending_reviews` 和短期 `mistake_submissions` 当前使用本机 ID/过期策略，不应直接充当永久变更 ID；`schedule_at` 对覆盖及待完成 token 的写入、`complete_at` 的记忆状态写入、`record_mistake_once` 的计数分别要由后续票识别持久同步操作与本机会话临时状态。

## Implementation steps

### 1. 固定操作契约和纯排序

- **Files or discovery point:** 新增 `replay.rs`；核对 `repository.rs` 的模块声明。
- **Change:** 定义规范 ID、版本化信封与前驱、独立发生时间；验证同源序号/前驱、自身引用、重复 ID 内容冲突；用确定性的拓扑排序产生统一顺序。实现前确定 ID 编码和序号溢出策略，并给同一输入集固定结果。
- **Outcome:** 与抵达次序、设备墙钟无关的全序；缺少依赖明确标记未就绪。
- **Verification:** 纯 Rust 表格测试：两端/三端因果链、互不相关并发、时钟倒退、随机排列；环及伪造重复拒绝。

### 2. 初始化空基线并建持久日志

- **Files or discovery point:** `repository.rs::initialize` / `connect` 与新增仓储模块；检查目前内联迁移及 `review_settings` 默认行。
- **Change:** 事务迁移新增设备身份/序号/基线与操作记录表及约束索引。首次生成设备身份须使用可靠随机源（依赖选择在实现时确认）；空库进入可重建模式。升级旧库先检查真实业务数据而非只看是否存在表；标记不可重建，保持原表和数据完整，不自动清库，也不由已有汇总制造日志。重复打开不得换身份或重置日志。
- **Outcome:** 新库持久身份稳定；旧库原业务功能和数据保持原样且重放被安全阻止。
- **Verification:** 临时 SQLite 文件新建/重开、旧 schema 加数据/重开、初始化失败回滚、默认设置不误判为历史的集成测试。

### 3. 落地原子本地提交与读取

- **Files or discovery point:** 新仓储模块；与 `repository.rs::replace`、`record_mistake_once` 的事务结构对照。
- **Change:** 在同一写事务中锁定序号、记录信封并调用注入的投影处理器，提交成功才对调用方返回；失败全部回滚。导出按来源连续序号分页，并以不可变规范内容校验重复身份；接口预留业务目标的稳定 ID 而非依赖 `entries.id`/`wordbooks.id`。空库测试投影先实现简单写/删操作，不修改现有业务命令语义。
- **Outcome:** 本地测试操作与日志原子出现；失败既无投影，也不消费不可恢复序号；增量读取可重试。
- **Verification:** 处理器抛错、唯一键失败、重开后继续写、并发本地写、分页边界及读回一致性的 SQLite 测试。

### 4. 收取、重建与恢复

- **Files or discovery point:** 同一仓储模块和测试投影；后续 T0002/T0003 可复用的投影处理接口。
- **Change:** 收取时校验身份、版本、内容与依赖；同身份同内容重复为无操作，冲突报错；缺失依赖持久暂存。依赖完整时计算规范全序，在事务内重建可重建投影并记录成功状态/水位；处理器失败则回滚，不宣称已应用。迟到且排序在既有操作之前时同样重建，避免按到达次序叠加结果。不可重建旧库及未知版本不进入投影。
- **Outcome:** 重启、中断、乱序和重复收取最终同序同态，失败后可从日志安全重试。
- **Verification:** 两个/三个临时库模拟不同交付排列、删/改冲突、依赖晚到、重复收取、异常注入与中途重启；比较日志顺序与投影状态而非仅比较变更数。

### 5. 固定下游接入约束与运行回归

- **Files or discovery point:** 模块内部 API 文档/测试；`src-tauri/src/wordbooks/schedule.rs` 的事务边界和 `src-tauri/src/wordbooks/mod.rs` 的命令清单。
- **Change:** 记录 T0002/T0003 对接规则：原有业务操作在同一事务内记录一次规范事件；远端重建不产生新的本地事件；跨设备引用改用稳定目标；本机选择与未结束练习不参加投影；真正全业务覆盖才由后续票验收。不新增网络或 UI 命令。
- **Outcome:** 后续票能分别接入内容操作和学习事件，而不误以为测试投影已同步真实业务数据。
- **Verification:** `cd src-tauri && cargo test`、`cargo fmt --check`；核对 `git diff` 未触及前端/配对，现有仓储与调度测试通过。

## Edge cases

| Condition | Expected behavior | Owning step or verification |
| --- | --- | --- |
| 本地投影处理失败、磁盘写入失败或事务提交失败 | 操作、序号及投影均不形成半成品；重试可重新提交 | 3 / 错误注入 |
| 同一 ID 重复到达但内容不同 | 拒绝并保持既有日志与投影，不能按 ID 静默忽略 | 1、4 / 冲突测试 |
| 子操作先于父操作抵达，或同源序号存在空洞 | 持久暂存但不提前应用；依赖补齐后按因果顺序计算 | 1、4 / 乱序测试 |
| 迟到并发修改排序在已应用删除前（或反之） | 按全量规范顺序重建，后重放者生效；两库最终相同 | 4 / 双端删改交叉测试 |
| 系统时钟相差数天或学习事件发生时间倒退 | 操作顺序不变；发生时间只交给后续学习语义计算 | 1、4 / 时钟测试 |
| 应用重启时记录存在、投影重建曾失败 | 重启读取持久状态并重试完整事务，重复接收无额外效果 | 4 / 故障重启测试 |
| 已有词书/收藏/学习数据旧库首次升级 | 原数据不删、不合成事件；重建入口拒绝覆写并给出明确状态 | 2、4 / 升级测试 |
| 未知版本、依赖环或不被授权来源 | 不投影；版本/图错误显式报告，来源鉴权留 T0004/T0005 且接口不默认转发 | 1、4、5 / 协议负例 |

## Verification strategy

| Behavior or risk | Method | Evidence |
| --- | --- | --- |
| 因果与并发全序 | 纯函数单测与顺序排列测试 | 任意到达顺序输出同样 ID 顺序；时钟不影响结果 |
| 原子性与身份持久性 | 临时 SQLite 集成测试 | 写入失败无单边状态；重开身份/序号不变，重复操作只应用一次 |
| 迟到操作与故障恢复 | 双端/三端投影测试 | 删除、修改、事件计数的终态一致；中断/重启后与一次性重放一致 |
| 旧库安全 | 旧 schema 含数据升级测试 | 原记录完好、无虚构日志、重放被拒；空库可初始化 |
| 回归 | `cd src-tauri && cargo test`、`cargo fmt --check` | 原有 wordbooks/review 测试通过且格式无误 |

## Risks and open questions

- **风险：** 全量重建成本会随日志增长；先测数千/数万条操作耗时和事务占用，再决定是否建立可验证的检查点/增量回放，不能牺牲迟到操作的正确性。
- **风险：** 现有业务写入尚未走日志，故本票不能声称已有业务操作已同步；T0002/T0003 必须逐一封闭绕过路径，并使重建时不再次发出本地日志。
- **待确认的实现细节：** 真实投影需保留哪些本机临时表、哪些表可以从空基线重建，应在 T0002/T0003 对接时以现有数据语义和测试确定；T0001 的接口必须允许明确划分，不能直接清空整个 SQLite 数据库。
- **风险：** 多设备因果前驱可能包含未直接配对的来源；T0005 必须按直接信任验证增量读取/收取可达性，拒绝缺失授权的操作，不得靠 B 转发 C 的数据来填补前驱。
