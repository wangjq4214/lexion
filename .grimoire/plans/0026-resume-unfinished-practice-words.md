# 先补未完成题，再安排复习抽词

- **Input:** `.grimoire/spec/0002-coverage-and-forgetting-curve-review-scheduling.md`、`.grimoire/adr/0011-count-practice-coverage-on-completion.md`、用户确认“未提交词优先于到期词”。
- **Date:** 2026-09-28
- **Status:** Proposed

## Summary

将“本轮选中”与“题目完成”分为独立的持久状态；按来源优先重排未完成词（限本轮容量），余量沿用原到期/新词分配。完成时原子更新覆盖和记忆；本地与 LAN 同步投影必须一致。不触及已有的字体/名称等用户工作区改动。

## Source intent and acceptance

- 排入本轮（包括未展示）不算覆盖，未提交中途退出仍可在同一来源下轮优先抽到；未完成数大于题数时只取题数且后续可继续抽。（步骤 1–3，测试 A）
- 答对、答错、跳过完成才记覆盖和记忆；未完成不更新记忆，重复反馈不重复计算。（步骤 2–3，测试 B）
- 词本/收藏/错题分别覆盖，同一词对同方向跨来源共享记忆；来源变化、重启及 LAN 同步重放后仍遵守选题规则。（步骤 1–4，测试 C）
- 不改考试随机抽词、答题统计和错题累计规则。（测试 D）

## Design impact

- **状态归属：** `src-tauri/src/wordbooks/repository.rs` 的 SQLite schema 承担来源范围的未完成选题身份；`review_coverage` 只记完成。不能仅使用按 30 天清理的 `pending_reviews` 作为唯一待练队列；已有 completion token 用于幂等反馈。
- **调度边界：** `src-tauri/src/wordbooks/schedule.rs` 本地和同步选取分支均从当前来源成员中过滤未完成候选，优先选它们再按原规则填空。未完成的已覆盖词也需优先，且同轮去重。
- **完成边界：** 本地 `complete_at` 与 `repository/learning.rs` 的 Schedule/Complete 投影负责 assignment→coverage 转换；同步事件须使用源设备稳定的来源身份（词本名、词对），而非远端本地 ID。同步重放的 reset/reapply 必须重建相同的派生状态。
- **迁移策略：** 保留不可溯源的历史本地覆盖和记忆，不臆测过去哪题未提交；对新选题按新规则执行。同步数据若可由学习事件复建，重放时由完成事件推导覆盖。避免删除历史学习进度。

## Implementation steps

1. **增加来源范围的持久待练身份。** 在 repository 初始化/同步投影中持久化选中但未完成的词对与选题身份/顺序；过期 completion token 不得抹掉待练资格；同一个词重复排入不同轮时，完成旧身份不误删更新的未完成身份。验证数据库重新打开及 replay 的状态。
2. **重排两条调度路径。** 在 `schedule.rs` 本地/sync 候选查询里把未完成放在到期和首次覆盖前，按题数截取，并从其他组排除相同词对；排入仅更新待练状态而非 `review_coverage`。验证不足题数、持续到期和重复选中。
3. **完成时原子记录覆盖和记忆。** 本地和 `repository/learning.rs` 同步投影将完成令牌绑定来源，完成时按当前成员写覆盖、清除此份待练并更新方向记忆；保留原有重试/幂等语义。核查 `src/routes/practice.tsx` 的退出、答错揭示和跳过边界；仅在确实必要时调整前端保存时机。验证答题与退出状态。
4. **测试与集成。** 扩展 `schedule.rs` SQLite/restart/sync replay 测试及相关 `src/App.test.tsx` 退出流程；Rust 测试、前端 Vitest、类型检查、改动范围格式检查；不改无关用户文件。

## Edge cases

| Condition | Expected behavior | Owning step |
| --- | --- | --- |
| 本轮刚排入但题目未展示即退出 | 下次同来源先抽到该词，不更新记忆 | 1–3，测试 A |
| 未完成题数大于下轮上限，同时存在到期词 | 先取上限内未完成词，余下继续待练 | 2，测试 A |
| 已完成过的词再次排入却未完成 | 仍先于到期和新词；原有已完成覆盖不消失 | 1–3，测试 B |
| 成员移除/重导入、重复完成、重放顺序变化 | 仅当前来源成员可抽；覆盖和记忆不重复/串源 | 1–4，测试 C |
| 老旧数据库没有可恢复的完成来源 | 不破坏历史覆盖与记忆，新安排按新语义 | 1，测试 C |

## Verification strategy

- **A（调度）：** SQLite 确认未提交/未展示→下轮优先、容量不足留待以后、无同轮重复和其余旧调度规则。
- **B（反馈）：** 正确/错误/跳过→覆盖+记忆；未完成→均不更新；同令牌多次反馈和跨轮旧令牌安全。
- **C（持久/同步）：** reopen、来源变更、双端同步重放顺序与已完成旧记录兼容。
- **D（回归）：** 练习 UI 退出和状态测试、Rust 全量模块测试、前端类型检查与受影响单测。

## Risks and open questions

- **同步一致性：** `LearningProjection` reset/replay 会删除旧覆盖并从事件重建；必须复核非事件化 legacy 迁移，不能只改本地路径。
- **答错揭示：** 已将答错、跳过和第三级提示的保存前移到完成动作，未保存成功时保留当前题与重试路径；异常强制关闭时网络写入是否落盘仍取决于持久层是否完成。
- **历史状态：** 用户确认旧版排入但未答的题不追溯恢复；保留既有历史覆盖和记忆，只对后续排题应用新语义。
